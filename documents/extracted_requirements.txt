Document 6 · What to build, the rules it must follow, delivery phases and acceptance · Version 1.1 · 19 September 2026 · Prepared by Parth Varma


How to use this document
This is the brief for the development team. Read sections 1 to 5 before writing any code. Every requirement has an ID (SA = Super Admin, CL = Client panel, PL = WhatsApp platform rule, NF = non-functional) — use these IDs in tasks, commits and questions. Before starting, return an estimate per phase using the table in section 12. No passwords, secrets or tokens are in this document; they are handed over separately (section 3).

1. The product
WB Assistant is a multi-client WhatsApp business messaging platform built on the official WhatsApp Business Platform (Cloud API). Businesses use it to talk to their own customers on WhatsApp: a shared team inbox, broadcast campaigns, chatbots, keyword automation and analytics. The closest reference product is getgabs.com.
It is a new product, built from scratch on the itfuturz-waba code. It keeps the WB Assistant name, but it is not a migration of the old unofficial WB Assistant (whatsapp-web.js): no code from that product is used. Every message goes through Meta's official Cloud API.
1.1 Who uses it
Small and medium Indian businesses — e-commerce, education, healthcare, real estate, restaurants, salons, services
Existing WB Assistant customers moving from the unofficial version
I T FUTURZ staff, who operate the platform from the Super Admin panel

8. WhatsApp platform rules — must be enforced in code
These come from Meta’s policies and API behaviour. Breaking them gets client numbers restricted or banned, and can put ITFuturz’s Meta approval at risk.
ID
Rule
PL-01
Business-initiated messages only to contacts who opted in. Store opt-in source and time
PL-02
Opt-outs (STOP) take effect immediately
PL-03
24-hour customer service window: free-form messages only within 24 hours of the customer’s last message. Outside it, approved templates only
PL-04
Template category must match its content. Promotional wording in a Utility template gets rejected or reclassified
PL-05
Messaging limits per number: new numbers start at 250 unique recipients per 24 hours; tiers rise automatically with good quality. Never exceed the current tier
PL-06
Throughput: about 80 messages per second per number by default. On error 130429, back off and retry
PL-07
Webhooks are delivered at least once. De-duplicate on the message ID (wamid)
PL-08
Verify X-Hub-Signature-256 on every webhook, computed over the raw request body. Reject anything invalid
PL-09
Acknowledge webhooks within about 2 seconds; process in the background queue
PL-10
Contacts are identified by BSUID (business-scoped user ID). Phone number may be missing for WhatsApp username users
PL-11
Client tokens expire after 60 days. A daily job warns 7 days ahead and triggers refresh or the reconnect flow
PL-12
Meta allows at most 200 new client onboardings per rolling 7 days
PL-13
Embedded Signup v4 only. v2 is retired on 15 October 2026
PL-14
No unofficial libraries (whatsapp-web.js, Baileys, Puppeteer automation) and no anti-ban behaviour (random delays, message variation to avoid detection)
PL-15
No contact scraping and no group messaging features
PL-16
Brand: no WhatsApp or Meta trademarks in product names or domains. "Built on the official WhatsApp Business Platform" is fine. Do not display an "Official Meta Partner" badge — ITFuturz is a Tech Provider, not a Meta Business Partner

11. Meta integration
11.1 Embedded Signup — how a client connects

Client clicks "Connect WhatsApp". The frontend opens Facebook Login for Business with our Configuration ID, asking for an authorisation code
Client logs in to Facebook, chooses or creates their business and WhatsApp account, and verifies their number
The frontend receives the code plus waba_id and phone_number_id, checks the message came from a facebook.com origin, and sends them to our server
Server exchanges the code for a business token (uses App Secret — server only)
Server subscribes our app to the client’s WABA so their webhooks reach us
Server registers the phone number for Cloud API with a 6-digit PIN
Server fetches number details and stores everything, token encrypted
Client sees their connected number, quality rating and messaging tier

Every step must be safe to retry. The development team must confirm exact v4 parameters and endpoints against Meta’s current official documentation and list the URLs used — not blog posts or reseller guides, which often describe older versions or a different setup.
11.2 Webhooks
One callback URL for the whole app: https://wbassistant.itfuturz.cloud/webhook
Each event is routed to the right client by phone_number_id or WABA ID. Unknown IDs are logged and acknowledged, never crash the handler
Subscribe to incoming messages and statuses, template status updates, phone number quality updates and account updates (exact field names confirmed in the Meta dashboard)

11.3 Meta dashboard steps done by ITFuturz
The development team supplies the values; ITFuturz enters them:

App settings → Basic → App domains: add wbassistant.itfuturz.cloud (after the landing page rewrite)
Facebook Login for Business → Settings: allowed domain and OAuth redirect URI for wbassistant.itfuturz.cloud
WhatsApp → Configuration: webhook callback URL, verify token, subscribed fields

17. Glossary
Term
Meaning
Cloud API
Meta’s official API for sending and receiving WhatsApp business messages
WABA
WhatsApp Business Account — owned by each client
Embedded Signup
Meta’s pop-up flow that lets a client connect their WhatsApp account to our platform
Tech Provider
ITFuturz’s status with Meta: we provide software; Meta bills clients directly for messages
Template
A pre-approved message format required to message a customer outside the 24-hour window
24-hour window
Period after a customer’s last message during which free-form replies are allowed
BSUID
Business-scoped user ID — Meta’s identifier for a WhatsApp user, used when the phone number is hidden
wamid
Unique ID of a WhatsApp message; used to avoid processing the same webhook twice
Quality rating
Meta’s GREEN / YELLOW / RED rating of a number based on blocks and reports
Messaging tier
How many unique customers a number may message in 24 hours (250, 2,000, 10,000, 100,000, unlimited)
Opt-in
The customer’s recorded permission to receive business-initiated messages
