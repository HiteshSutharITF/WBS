## 1. What we are building

**WB Assistant** — a new multi-client WhatsApp business platform (similar to getgabs.com) on the
**official WhatsApp Cloud API**, built from scratch on the `itfuturz-waba` code. **No code from the
old unofficial WB Assistant (whatsapp-web.js) is used** — only the name and domain carry over. Product brand: WB Assistant. Company behind it: I T FUTURZ.
The Meta app is still named "ITFuturz Messaging Platform". ITFuturz is a Meta **Tech Provider**:

- Each client business connects **their own** WhatsApp number through **Embedded Signup**
- Meta bills each client **directly** for messages (client adds their own card in Meta)
- ITFuturz charges clients a **software subscription** only
- ITFuturz never owns or pays for client numbers

```
                ┌──────────────────────────────┐
                │  SUPER ADMIN PANEL (ITFuturz) │  ← our staff
                │  all clients, health, plans   │

        └──────────── WhatsApp Cloud API (Meta) ──────┘
```

One codebase, one database, one Meta app. Every row carries a `tenant_id`.

## 3. Starting point

Already built and working against the live API (`itfuturz-waba.zip`):

- Node.js + TypeScript + Express, run with `tsx` (no build step)
- `src/lib/graph.ts` — send template, send text, create/list templates, list phone numbers

## 5. Super Admin panel — features

| Screen | Contents |
|---|---|
| Dashboard | Total clients, active today, messages sent/received today, failed messages, new signups this week |
| Clients list | Business name, connected number, plan, status (active / needs_reconnect / suspended), signup date, search and filters |
| Client detail | WABA ID, phone number ID, quality rating (GREEN/YELLOW/RED), messaging limit tier, **token expiry date**, templates count, message volume chart, users |
| Health alerts | Tokens expiring within 7 days · quality rating dropped · number disconnected · webhook errors |
| Plans | Create plans with limits (users, broadcasts/month, flows, contacts) — Gabs sells Basic / Plus / Pro this way |
| Subscriptions | Plan per client, renewal date, paid/unpaid, suspend/reactivate |
| Onboarding counter | New clients in the last rolling 7 days vs Meta's cap of **200** |
| Audit log | Every super-admin/support action: who, what, which client, when |
| Announcements | Banner shown to all client panels (maintenance, new features) |

**Privacy rule — important.** Our Privacy Policy says staff access is limited to what the role
requires. So the Super Admin panel shows **counts, statuses and health**, not client message
content. If support ever needs to open a client's conversations ("login as client"), it must:
require a written reason, be time-limited, and be recorded in the audit log.

## 7. Build order

**Phase 0 — Domain and hosting (first)**
- **Before** this domain is added anywhere in the Meta dashboard: the current landing page on
  wbassistant.itfuturz.cloud (the old unofficial whatsapp-web.js product) must be rewritten for the
  official product — remove anti-ban, human-like delay, message-variation, contact-extraction and
  group features; add "Built on the official WhatsApp Business Platform" and state that Meta message
  charges are billed separately. The old unofficial app must be moved off this domain or shut down.
- Deploy on `https://wbassistant.itfuturz.cloud` with valid HTTPS. Must serve directly — **no redirect**
  (Facebook Login Strict Mode rejects redirecting domains)
- PostgreSQL, a job runner/queue for broadcasts and scheduled jobs, daily DB backups

**Phase 1 — Multi-tenant core** (see `claude-code-prompt-embedded-signup.md`)
1. Tenants, users, roles, login
2. Embedded Signup → token exchange → subscribe app to client WABA → register phone number
3. Client tokens encrypted at rest (AES-256-GCM)
4. Webhook routing by `phone_number_id` → correct tenant
5. Token expiry job (60-day tokens) + "reconnect" banner
6. Super Admin: clients list, client detail, health alerts, audit log
7. Test: tenant A can never read tenant B's data

**Phase 2 — Client panel essentials:** inbox, contacts, templates, broadcast, basic bot, analytics

**Phase 3 — Growth features:** flows, drip, AI, integrations, widget

**Then** pilot with 1–2 friendly clients before any public launch.

## 8. Rules that are not optional

- **Only message opted-in contacts.** Store opt-in source and date. Honour STOP immediately
- **24-hour window:** free-form replies only within 24h of the customer's last message; after that, approved template only. The inbox must show this
- **Messaging limits:** new numbers start at 250 unique recipients / 24h. Broadcasts must respect the tier and back off on error `130429`
- **Webhooks are delivered at least once** — dedupe on `wamid`
- **Contacts keyed on BSUID**, phone nullable — WhatsApp usernames mean phone can be missing
- Never call the Graph API from the browser. All Meta calls are server-side
- No anti-ban tricks (random delays, message variation) — that was the old whatsapp-web.js version's approach and has no place here

## 9. What needs a human in the Meta dashboard (Parth / ITFuturz)

After the app is deployed, ITFuturz does these in the Meta dashboard — the developer tells us the values:

1. **Publish** the app (sidebar → Publish) — until Live, real clients cannot connect
2. **Webhook:** WhatsApp → Configuration → Callback URL `https://wbassistant.itfuturz.cloud/webhook` + verify token → subscribe to `messages`, template status updates, phone number quality updates (confirm exact field names in the dashboard)
3. **App domains:** add `wbassistant.itfuturz.cloud` in App settings → Basic (only after the landing page rewrite in Phase 0)
4. **Facebook Login for Business → Settings:** add `https://wbassistant.itfuturz.cloud` to allowed domains / valid OAuth redirect URIs
5. Add the developer under **App roles → Developer**
